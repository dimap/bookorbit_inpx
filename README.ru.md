добавленной поддержкой **архивных каталогов INPX** (Flibusta / FLibrary / FlibRusEc).

## Что это за форк?

Это **[dimap/bookorbit_inpx](https://github.com/dimap/bookorbit_inpx)**, форк проекта
[BookOrbit](https://bookorbit.app). В нем сохранено все, что умеет оригинал (веб-читалки,
синхронизация с Kobo и KOReader, метаданные, статистика, многопользовательский режим и многое
другое), и добавлена возможность импортировать и читать книги из **архивных каталогов INPX**.

Каталог INPX это ZIP, внутри которого лежат индексы `.inp` (базы SQLite) вместе с архивами книг,
на которые они ссылаются. Форк читает книги прямо из этих архивов при открытии и скачивании,
поэтому большая библиотека в стиле Flibusta (сотни ГБ) хранится на диске ровно один раз, ничего
не копируется и не распаковывается.

Изменения форка находятся в ветке **`main`** (разработка ведется в `feat/inpx-support`). В `main`
оригинального BookOrbit их нет.

## Чем отличается от оригинального BookOrbit

### Поддержка архивов INPX и Flibusta

- **Библиотеки из архивов**: зарегистрируйте файл `.inpx`, запустите импорт и просматривайте весь
  каталог. Книги отдаются прямо из архива при открытии или скачивании.
- **Парные шарды `.7z`**: поддерживается раскладка FlibRusEc / FLibrary, где каждый индексный шард
  `.inp` идет в паре с одноименным шардом `.7z`, в котором лежат сами файлы книг.
- **Без распаковки шардов целиком**: обогащение открывает по одной книге из шарда. Шард никогда не
  распаковывается полностью, поэтому импорт не требует дополнительного места на диске.
- **Определение формата по содержимому**: реальный формат определяется по байтам файла (ZIP EPUB,
  7z или FB2), а не по расширению в индексе. EPUB из FLibrary, упакованные как 7z, тоже
  обрабатываются.
- **Нативный читатель 7z**: читает 7z-архивы (включая solid) через системный бинарник `7z`, а для
  обычных EPUB используется чтение ZIP по смещениям.
- **Обложки из соседних архивов**: FLibrary хранит обложки вне книг, в архиве `covers/`, названном
  по самому архиву книги (`covers/f.fb2-009373-367300.zip`, а не по диапазону книжных id). Запись
  обложки определяется по lib id / имени файла из INPX (`814211`, `814211.jpg`) и читается во время
  работы, поэтому подходит любая раскладка зеркала.
- **Аннотации из соседних архивов**: описания книг читаются из `etc/annotations.7z` по имени архива
  книги и имени файла и сохраняются как описание книги.
- **Портреты и биографии авторов**: FLibrary хранит фото авторов в `etc/authors/pictures/*.zip|7z`, а
  биографии в `etc/authors/*.zip|7z`, ключ - MD5(имя автора). При импорте шарды один раз
  просматриваются и ключи индексируются; портрет или биография читаются при первом открытии страницы
  автора, поэтому импорт больших библиотек остается быстрым.
- **Обогащение метаданными**: данные FB2 (название, авторы, серия, ISBN, описание, жанры, обложка)
  извлекаются из файла; EPUB из FLibrary в 7z получают обложку и описание из соседних архивов.
  Обогащение можно возобновлять, каждая книга обрабатывается один раз, прогресс виден в реальном
  времени.
- **Виртуальные папки**: для каждого архива создается виртуальная папка библиотеки
  `inpx://<archiveId>`. Сканер и слежение за файлами их пропускают, поэтому книги из INPX никогда не
  помечаются как отсутствующие. Переименование и перемещение для файлов из архива запрещены.
- **Интерфейс и прогресс**: панель "INPX archives" в деталях библиотеки и прогресс по WebSocket для
  фаз индексации и обогащения.

### Эксплуатационные исправления

- В runtime-образ Docker добавлен системный пакет `7zip`, нужный читателю архивов.
- Postgres получает `shm_size: '1gb'`, чтобы тяжелые запросы каталога (страницы серий, подсчеты) не
  падали из-за стандартного `/dev/shm` в 64 МБ.
- Удаление большой библиотеки теперь выгружает книги порциями (по 1000 за раз, с отключением
  statement timeout внутри порции), а не одним каскадом, который упирался в 30-секундный таймаут.

Полное описание модели данных, маршрутов API и структуры модулей: [docs/INPX_SUPPORT.md](docs/INPX_SUPPORT.md).

## Установка (Docker, сборка из исходников)

Форк не публикуется в GHCR, поэтому образ собирается из этого репозитория. В runtime-образ входит
нативный бинарник `7z`, необходимый читателю архивов.

Клонируйте репозиторий и создайте папки:

```bash
git clone https://github.com/dimap/bookorbit_inpx.git bookorbit
cd bookorbit
mkdir -p books data/app data/postgres
cp .env.example .env
```

Отредактируйте `.env` и задайте обязательные значения:

```dotenv
APP_URL=http://your-server-ip:3000     # адрес, по которому вы будете открывать BookOrbit
BOOKS_HOST_PATH=./books                # папка на сервере, где лежат файлы книг

POSTGRES_PASSWORD=         # пароль базы данных         - openssl rand -hex 24
JWT_SECRET=                # подпись токенов входа      - openssl rand -hex 32
SETUP_BOOTSTRAP_TOKEN=     # токен мастера настройки    - openssl rand -hex 16
```

Дальше выберите один из двух способов запуска.

### Вариант A: готовый compose (собирает образ сам)

Файл `docker-compose.build.yml` собирает образ из этого же чекаута и запускает стек. Переменная
`APP_IMAGE` в нем не используется.

```bash
docker compose -f docker-compose.build.yml up -d --build
```

### Вариант B: собрать образ вручную

Сначала соберите образ, затем задайте `APP_IMAGE` в `.env` и запустите стандартный compose:

```dotenv
APP_IMAGE=bookorbit-inpx:latest        # образ, собранный ниже, а НЕ ghcr.io/bookorbit/bookorbit
```

```bash
docker build -t bookorbit-inpx:latest .
docker compose up -d
```

Откройте `http://your-server-ip:3000` и завершите настройку с помощью `SETUP_BOOTSTRAP_TOKEN`.
Миграции базы данных применяются автоматически при старте контейнера.

На NAS или любом хосте, где папка с книгами принадлежит пользователю не с UID 1000, задайте также
`PUID` и `PGID` под владельца. Узнать их можно командами `id -u` и `id -g` от имени владельца. Ошибки
здесь - самая частая причина проблем с правами при первом сканировании.

При желании задайте `LIBRARY_BROWSE_ROOT=/books`, чтобы выбор папки библиотеки начинался с `/books`,
а не с `/`.

### Обновление

```bash
git pull --ff-only
docker compose -f docker-compose.build.yml up -d --build
```

### Импорт библиотеки INPX

1. Положите каталог `.inpx`, его шарды книг (`.7z` / `.zip`) и папки `covers/` / `images/` (если есть)
   в папку на хосте, смонтированную как `/books` (это `BOOKS_HOST_PATH` выше).
2. В BookOrbit создайте библиотеку и откройте ее панель.
3. В разделе **INPX archives** зарегистрируйте абсолютный путь к файлу `.inpx` внутри контейнера
   (например `/books/flibusta.inpx`) и запустите импорт.
4. Следите за прогрессом в панели. Позже можно повторно нажать **Extract metadata**, чтобы добрать
   обложки и описания для книг, импортированных без них.

Если каталог разбит на легкие шарды по языкам, зарегистрируйте каждый `.inpx` в одной и той же
библиотеке.

## Возможности

Перечисленное ниже унаследовано от оригинального BookOrbit и форком не изменялось.

### Чтение и синхронизация

- **Встроенные веб-читалки**: книги (EPUB, KEPUB, MOBI, AZW3, AZW, FB2), PDF, комиксы (CBZ, CBR, CB7) и аудиокниги (M4B, MP3, M4A, OPUS, OGG, FLAC) без дополнительных плагинов.
- **Тройная синхронизация (Kobo + KOReader + BookOrbit)**: прогресс и пометки синхронизируются в обе стороны между устройствами Kobo, KOReader и веб-читалкой BookOrbit. Продолжайте с любого места, где остановились на другом устройстве, включая выделения и удаления.
- **Плагин для KOReader**: браузер каталога на устройстве с поиском, скачиванием, управлением статусом и рейтингом, а также полная синхронизация прогресса и пометок.
- **Пометки и выделения**: выделения из веб-читалки, KOReader и Kobo сливаются в один центр с поиском. Фильтры по цвету, стилю и источнику; экспорт в Markdown, CSV или JSON.
- **Синхронизация с Hardcover, Readwise и StoryGraph**: отправка статуса, прогресса, дат чтения и рейтингов в Hardcover по настраиваемым событиям; статуса и прогресса в The StoryGraph; новых пометок и заметок в Readwise по мере создания, как из веб-читалки, так и с синхронизированных устройств. Историю чтения из Hardcover можно подтянуть и заполнить пустые записи BookOrbit.
- **Статистика, цели и достижения**: время чтения по дням, тепловые карты, серии дней и здоровье библиотеки, а также годовые цели, месячные испытания и 50+ достижений в пяти категориях. Reading DNA описывает стиль чтения по фактической истории сессий.

### Управление библиотекой

- **Несколько библиотек**: изоляция контента с отдельными папками, своими правилами сканирования и приоритетами форматов.
- **14 поставщиков метаданных**: Google Books, Open Library, Amazon, Goodreads, Kobo, Hardcover, Audible, Audnexus, Libro.fm и iTunes, плюс ComicVine для комиксов, RanobeDB для ранобэ и Aladin и Lubimyczytać для корейского и польского каталогов. Обложки берутся отдельно из iTunes, DuckDuckGo и AudiobookCovers.
- **Умные подборки и коллекции**: организуйте коллекцию курируемыми списками и динамическими фильтрами на основе правил.

### Платформа и доставка

- **Многопользовательский режим и SSO**: гранулярные права на пользователя и изолированные данные чтения, с нативной поддержкой Authentik, Keycloak и Authelia через OIDC.
- **Многоязычный интерфейс**: переводы сообщества ведутся на [Crowdin](https://crowdin.com/project/bookorbit). Текущие языки и инструкции для переводчиков: [руководство по локализации](docs/LOCALIZATION.md).
- **Доставка контента**: поддержка OPDS для совместимых приложений, Send-to-Kindle по email и загрузка файлов перетаскиванием в браузере.
- **Автоматический импорт**: настройте папку Book Dock для импорта без ручных действий.

## Плагин для KOReader

Плагин BookOrbit для KOReader добавляет синхронизацию прогресса, двустороннюю синхронизацию пометок и встроенный браузер каталога: переходите, ищите и скачивайте книги из библиотеки, не покидая устройство.

![Плагин BookOrbit для KOReader с панелью, поиском по каталогу и карточкой книги](docs/images/koreader-plugin-preview.png)

1. В BookOrbit откройте **Settings > KOReader**, при необходимости создайте учетные данные и нажмите **Download Plugin**.
2. Распакуйте `bookorbit.koplugin.zip`.
3. Скопируйте `bookorbit.koplugin` в `koreader/plugins/` на устройстве.
4. Перезапустите KOReader и откройте книгу.
5. Подключитесь через **Tools > BookOrbit Sync**.

Загруженный плагин уже настроен на адрес вашего сервера и учетные данные, поэтому вводить их на устройстве не нужно. Полная настройка и параметры синхронизации: **[bookorbit.app/koreader-plugin](https://bookorbit.app/koreader-plugin)**.
